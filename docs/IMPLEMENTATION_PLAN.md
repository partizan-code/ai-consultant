# Минимальная версия AI-консультанта для Instagram

Согласовано 20 ноября 2026 года. Документ предназначен для продолжения реализации
в новом чате. Само сохранение плана не означает начала реализации.

## 1. Функции первой версии

Бот консультирует по мягкой мебели на русском языке, выясняет потребность и собирает
заявки через Umnico.

- Текстовые сообщения Direct и подготовка личного ответа на каждый новый комментарий.
- Импорт существующей переписки для контекста и просмотра, без ответов на старые сообщения.
- Консультации по локальной базе знаний: Markdown, TXT и CSV.
- Заявка: имя, телефон, тип мебели, размеры, бюджет, город и срок покупки. Неполную
  заявку тоже сохраняем.
- Автоответы либо одобрение черновиков — переключаются в панели.
- Ручные ответы, пауза и возобновление бота в отдельном чате.

Расписание и проверку часов работы исключаем. Расчёт стоимости и анализ изображений
откладываем. Пока база знаний пуста, бот уточняет потребность и собирает контакты,
не придумывая сведения о товарах.

## 2. Простой технический состав

- **FastAPI** — приём webhook, обработка сообщений и API для панели.
- **Streamlit** — локальная панель одного администратора.
- **SQLite** — история, заявки, черновики, задания обработки и настройки.
- **HTTPX** — обращения к Umnico и OpenRouter.
- Сохраняем Python 3.13, mise + uv и существующий Loguru.

Начальная модель — `openai/gpt-6.1-sol` через OpenRouter. Все параметры и значения
по умолчанию задаются через `config.py`; секреты загружаются из окружения или `.env`.
Выбранная через панель модель сохраняется в SQLite и применяется к следующим запросам.

База знаний находится в `knowledge_base/`. Используем простой поиск по текстовым
фрагментам, без отдельной векторной БД и дополнительных AI-сервисов. Обновление
материалов — кнопкой в панели.

## 3. Структура и требования к коду

Разделить приложение на логические модули:

- **Конфигурация и запуск** — загрузка параметров, логирование, запуск backend и панели.
- **Клиенты интеграций** — отдельные модули Umnico и OpenRouter.
- **Обработка сообщений** — маршрутизация, подготовка контекста, генерация и отправка ответа.
- **Знания и заявки** — чтение материалов, поиск, извлечение и сохранение потребности клиента.
- **Хранение** — SQL-запросы и операции с SQLite.
- **Web API и панель** — тонкие обработчики и отдельные функции отображения.

Правила реализации:

- Небольшие функции с одной понятной задачей и явными аргументами.
- Типизация, понятные имена, простые модели данных.
- Композиция вместо сложных иерархий наследования.
- HTTP-запросы, SQL и бизнес-логика разделены.
- Классы использовать для объектов с состоянием, например API-клиентов; остальные
  операции оформлять функциями.
- Не вводить универсальные фабрики, контейнеры зависимостей, собственные фреймворки
  и абстракции для единственной реализации.

## 4. Панель и обработка

Три раздела панели:

- **Чаты и заявки:** переписка, комментарий и связанный пост, карточка клиента,
  черновик, ручной ответ, пауза бота.
- **Состояние:** последние обращения к Umnico/OpenRouter, результат, время ответа
  и последняя ошибка. Отдельный мониторинг сети не добавляем.
- **Настройки:** модель, автоответы/одобрение, обновление базы знаний.

Поток обработки: принять событие → сохранить → получить контекст и материалы →
подготовить ответ и обновить заявку → отправить либо показать черновик.

Оставить необходимые меры надёжности: тайм-ауты API, защита от повторной обработки,
последовательная обработка одного чата и отсутствие слепого повтора отправки при
неизвестном результате. Ручной ответ ставит бота на паузу; новые сообщения делают
старый черновик неактуальным.

Перед подключением отправки сверить непроверенные методы Umnico: историю, ответ
в Direct после комментария, идентификаторы отправителя и защиту webhook. Если личный
ответ через подключённый канал недоступен, показывать причину в панели. Панель
работает на localhost, webhook — через tuna; административные операции защищены
отдельным токеном.

## 5. Порядок реализации и проверка

1. Конфигурация, хранение и клиенты API.
2. Приём событий, импорт истории и отправка текста.
3. База знаний, консультации и заполнение заявки.
4. Панель, черновики, ручные ответы и выбор модели.

Минимальные автономные тесты: разбор событий, повторная доставка, отсутствие ответов
при импорте истории, сохранение заявки, выбор модели, пауза и одобрение ответа.
Сеть подменяется, БД временная. После изменений — штатные проверки Ruff и pytest.
Реальная отправка проверяется отдельно на согласованном тестовом аккаунте.
