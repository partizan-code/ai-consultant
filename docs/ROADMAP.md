# Состояние и дальнейшие действия

[Главная](../README.md) · [Границы проекта](IMPLEMENTATION_PLAN.md) · [Проверки](IMPLEMENTATION_PROGRESS.md)

Актуально на 22 ноября 2026 года. Основные возможности первой версии реализованы:
приём событий, общая переписка Direct и комментариев одного обращения, импорт
истории, консультации, заявки и панель администратора. Сценарии Direct проверены.
Production и staging развёрнуты на VPS, рабочий канал переключён на постоянный
домен. На сервере подтверждены входящие сообщения, подсказки и автоответы в Direct.
Проверка защищённого входа и работы панели не заменяет полную визуальную приёмку.

## Основной принцип продукта

Приложение разрабатывается как автономный ИИ-агент. После настройки он должен
самостоятельно обрабатывать обращения, консультировать клиентов и собирать заявки
без открытой панели и постоянного участия менеджера. Весь интерфейс предназначен
для настройки и отладки, включая проверку качества и разбор проблем с ручным
вмешательством. Постоянная работа менеджеров в приложении не планируется.

Развитие backend, интерфейса и интеграций подчиняется этому принципу. Приоритет —
качество автономных ответов, надёжная обработка событий и отправок, восстановление
после сбоев и наблюдаемость. Сейчас новые переписки создаются на паузе и требуют
ручной активации: это ограничение текущей реализации, которое предстоит устранить.

## План развития и приоритеты

План верхнего уровня согласован 21 ноября 2026 года. Детализация задач, оценки
и сроки выполняются отдельно перед реализацией каждого этапа. Невыполненные пункты
описывают будущие изменения; завершённые отмечены отдельно. P0 — ближайший этап, P1 — следующий,
P2 — дальнейшие интеграции, P3 — отложенные расширения.

### P0. VPS и управляемый выпуск версий

Первое размещение на существующем VPS Timeweb выполнено. Оба окружения используют
релиз `7179303`, Python 3.13.18, mise + uv, один процесс backend и отдельные SQLite.
Полное состояние, пути, порты и команды — в [инструкции эксплуатации](DEPLOYMENT.md).

- [x] Неинтерактивный запуск через `PUBLIC_BASE_URL`, отдельные local/staging/production,
  явный файл окружения и блокировка внешних API на staging.
- [x] Systemd от отдельных сервисных пользователей: установлены шаблоны из
  репозитория, включены автозапуск и `Restart=on-failure`, проверены units,
  перезапуск, состояния сервисов и loopback health.
- [x] DNS и Nginx для `ai.exprofit.by`, HTTPS, активный таймер certbot и deploy-hook
  reload Nginx; пробное продление с выполнением hook прошло успешно.
- [x] Streamlit за Nginx Basic Auth поверх HTTPS, передача WebSocket, отдельный
  защищённый токеном маршрут webhook. JSON admin API остаётся на loopback;
  секретный путь исключён из журналов нового виртуального хоста.
- [x] Раздельные код, данные, секреты, пользователи и `.venv`; создана новая рабочая
  база без переноса локальной истории. Staging доступен через SSH-туннель.
- [x] Ручные копии SQLite через backup API, проверка целостности; для production-копии
  проверены восстановление во временный каталог и чтение данных.
- [x] Переключение рабочего webhook с tuna на постоянный домен: локальный backend
  остановлен, прежняя активная регистрация отключена, сообщения поступают на VPS.
- [x] OpenRouter через локальный Xray/Red Shield VPN; добавлен явный прокси только
  для OpenRouter, сохранены прямой маршрут Umnico и запрет сети в staging.
- [x] Ручной выпуск через GitHub: отдельные каталоги релизов, зависимости по `uv.lock`,
  staging → тот же SHA в production, резервная копия перед переключением, health
  и проверка тестового Direct. Сохранены `main` и её upstream `origin/main`.
  Предыдущий релиз оставлен, процедура отката описана; фактический откат не выполнялся.

Осталось в эксплуатации и выпуске версий:

- [ ] Настроить автоматические бэкапы, срок хранения и копии за пределами VPS.
- [ ] Проверить перезагрузку VPS, восстановление при падении сервиса и прокси,
  практический откат релиза и обнаружение недоступности приложения.
- [ ] Перед обновлением Xray проверить поддержку gRPC у клиента и провайдера:
  текущая версия предупреждает об устаревании транспорта.
- [ ] Автоматизировать проверки и доставку через GitHub Actions с ручным
  подтверждением production-релиза. Пока деплой ручной; коммит, push и публикация
  выполняются только при соответствующем разрешении.

После будущего переноса UI сохраняются VPS, домен и Nginx, меняется маршрутизация
интерфейса. Развёртывание текущей Streamlit-панели не закрывает задачи нового UI.

### P0. Качество консультаций и эксплуатационная готовность

- [ ] Спроектировать, реализовать и проверить автономный запуск новых переписок
  после настройки агента, без ручного включения каждого чата. Сохранить возможность
  явной паузы для отладки; отдельно определить поведение существующих переписок

- [ ] Проверить полный цикл без открытой панели: новое обращение → консультация
  → сохранение полной или частичной заявки. Проверить перезапуск backend, повторные
  события, временные сбои и обнаружение ситуаций, требующих вмешательства.
  На VPS уже подтверждены входящие сообщения, подсказки и автоответы в Direct;
  это не полная проверка всех перечисленных условий и собранных полей заявки.
- [x] Устранить обнаруженные противоречия промпта и базы: область ограничена диванами,
  порог 2500 BYN перенесён в базу; уточнены доставка, квалификация, отказ от данных,
  график, изображения и неподтверждённые действия. Добавлены операции накопления
  характеристик и отзыва полей, лимит ответа 450 символов и признак прежнего упоминания
  оплаты по сохранённой переписке. Схема SQLite не изменена.
- [x] Подготовить обезличенные [сценарии проверки консультаций](CONSULTATION_CHECKS.md).
- [ ] Оценить ответы выбранной модели на этих сценариях, отдельно проверяя факты,
  диалог и поля заявки. Автономные тесты проверяют контракт и обработку, но не качество
  реальных ответов модели. Сохранение отказов клиента за пределами короткой истории
  и распознавание произвольных перефразирований оплаты пока не гарантируются.
- [ ] Проверить актуальность материалов бизнеса в `knowledge_base/` и качество ответов
  по ассортименту, характеристикам, доставке и разрешённым условиям. Справочник LEX'S
  очищен от других категорий. Владелец подтвердил нижний порог диванов и раздельную
  оплату доставки и погрузки; остальные факты требуют проверки по первоисточникам.
  Характеристики конкретных моделей и точный порядок учёта километров отсутствуют.
  Все документы передаются модели целиком, без поиска и нарезки.
- [ ] Завершить браузерную приёмку текущей панели: размещение сообщений, прокрутка,
  обновления, подсказки, сохранение ввода и ручная отправка.
- [ ] Уточнить контракт подписи webhook Umnico и поддерживаемый способ проверки запросов.
  Сейчас доступ ограничен секретным URL.
- [ ] Определить показатели автономного пилота: доля обращений без ручного
  вмешательства, качество и полнота заявок, время автоответа, ошибки и причины
  вмешательства. Пороговые значения согласовать отдельно; расширять использование
  автоответов по результатам оценки. Подсказки использовать для предварительной
  проверки качества и отладки.

### P1. Переход на FastAPI + Jinja2 + HTMX

Целевая панель — серверный HTML на Jinja2, частичные обновления через HTMX
и небольшие JavaScript-модули для поведения браузера. На этом этапе остаётся
одна административная учётная запись для настройки и отладки автономного агента.
Функции постоянного рабочего места менеджера не являются целью переноса.

- [ ] Выделить интерфейс в отдельный каталог `ui/` внутри существующего Python-пакета:
  маршруты, `templates/` с фрагментами и `static/` с CSS и JavaScript.
  Сохранить существующую структуру backend и один репозиторий. Интерфейс развёртывается
  вместе с FastAPI.
- [ ] Сохранить операции с данными, консультациями и отправкой в общих функциях приложения.
  HTML-маршруты и JSON API должны использовать общую логику; шаблоны только отображают
  подготовленные данные, UI не зависит от конкретного внешнего коннектора.
- [ ] Предусмотреть вход одной учётной записи, серверную сессию, выход и CSRF-защиту
  изменяющих запросов. `ADMIN_TOKEN` остаётся серверным секретом.
- [ ] Сначала перенести сквозной сценарий: вход → выбор чата → история → ручной ответ
  → обновление результата. Затем перенести подсказки, карточку клиента, паузу, импорт,
  настройки и состояние API до функционального паритета с текущей панелью.
- [ ] Сохранить независимое обновление списка чатов и истории; подсказки генерировать
  только по кнопке с заменой текста в редакторе без подтверждения. Редактор
  не заменять по таймеру. Предусмотреть черновики, сохранение прокрутки, защиту
  от поздних ответов запросов при смене чата и восстановление результата отправки
  после перезагрузки без повторной отправки вслепую.
- [ ] Сначала сохранить периодический опрос API с текущими интервалами. Переход
  на SSE или WebSocket рассматривать отдельно по задержкам и нагрузке.
- [ ] Подготовить изолированные проверки нового UI, браузерную приёмку, упаковку
  шаблонов и статики и инструкцию запуска. После переключения удалить Streamlit
  и его зависимости; проверки backend сохранить, проверки Streamlit заменить.

## Ближайшая проверка текущей версии

Перед обновлением установки со старой несовместимой схемой SQLite нужна отдельная
миграция по ссылке внизу. Обновления VPS `d6508fa` → `3f4022c` → `7179303`
не требовали миграции рабочей базы. Для `7179303` прошли 476 автономных
Python-тестов, 27 JavaScript-тестов и Ruff; после деплоя проверены сервисы,
health обоих окружений и защита маршрутов по HTTPS.
Защищённый вход в панель и её основные функции на VPS проверены. Отдельно остаётся
визуальная приёмка: размещение сообщений, прокрутка при новых сообщениях и ручной
отправке, сохранение позиции при чтении истории выше. Реальные API и рабочая база
в автономных проверках не используются.

## Ограничения и риски эксплуатации

- Отправка с неопределённым результатом блокирует новые отправки в общей переписке.
  Автоматического повтора и ручного сброса нет: сначала нужно установить результат.
- При нескольких связанных каналах Direct панель не выбирает маршрут ручного ответа.
  Такой случай требует уточнения маршрута.
- Проверки интеграции относятся к подключённому тестовому аккаунту. Для другого
  аккаунта необходимо проверить права, каналы и сотрудника-отправителя Umnico.
- Ответы модели зависят от полноты и актуальности материалов и соблюдения инструкции.
  База знаний передаётся целиком, без поиска фрагментов. Отдельной программной
  проверки товарных утверждений нет; до проверки качества разумно использовать
  паузу с подсказками для отладки и приёмки.
- Используется один процесс backend и панель одного администратора: Streamlit
  слушает loopback, внешний доступ защищён Nginx Basic Auth поверх HTTPS.
  Несколько работников backend и многопользовательская работа потребуют доработки.
- Автоматические и внешние бэкапы пока отсутствуют; ручные копии на том же VPS
  не защищают от потери сервера. OpenRouter зависит также от локального прокси.
- История импортируется только для известных приложению обращений. Автоматический
  поиск всех старых обращений не реализован.
- Фото отображается по ссылке Umnico: срок жизни ссылки и доступность изображения
  зависят от внешнего сервиса. Изображения не анализируются моделью.
- SQLite содержит переписку и контакты. Перед переносом или изменением схемы нужна
  резервная копия, а доступ к файлу базы следует ограничить.
- При смене адреса туннеля старые webhook Umnico не удаляются автоматически.
  Со временем можно достичь лимита регистраций; записи нужно проверять в Umnico.

  по таймеру, начальную отметку существующей истории как прочитанной и защиту от

  срок не определён.

## За пределами текущего объёма

Расписание и часы работы не входят в первую версию. Расчёт стоимости и анализ
изображений отложены. Сроки и объём расширений не определены.

Для базы со старой несовместимой схемой нужна [отдельная миграция SQLite](MIGRATION_SUGGESTIONS.md).
