# Состояние и дальнейшие этапы

[Главная](../README.md) · [Исходный план](IMPLEMENTATION_PLAN.md) · [Журнал](IMPLEMENTATION_PROGRESS.md)

Состояние документации актуализировано 21 ноября 2026 года по текущему коду
и журналу прогресса. Четыре шага реализованы в пределах описанных ниже сценариев;
это не означает завершения всех проверок интеграции на реальном аккаунте.

Исходный план сохранён как согласованный объём первой версии. Его раздел
«Контекст для нового чата» и ранние записи журнала описывают состояние на момент
их создания. Для текущего статуса используйте этот документ, для истории решений
и результатов проверок — журнал. Итоговая проверка Direct и автономного набора
выполнена 21 ноября 2026 года; результаты приведены ниже.

## Состояние реализации

| Шаг плана | Реализовано |
| --- | --- |
| 1. Конфигурация, хранение и клиенты API | Настройки, SQLite, клиенты Umnico/OpenRouter, тайм-ауты и безопасные ошибки |
| 2. События, история и отправка | Webhook, дедупликация, импорт без ответов на старые сообщения, отправка Direct и учёт неопределённого результата |
| 3. База знаний, консультации и заявки | Поиск по Markdown/TXT/CSV, контекст переписки, ответы модели и сохранение неполной заявки |
| 4. Панель и управление | Чаты и заявки, состояние API, черновики и одобрение, ручной ответ, пауза, выбор модели, режим автоответов и обновление знаний |

Панель также автоматически обновляет выбранный чат каждые 3 секунды и показывает
чаты по Instagram-логину клиента, если он получен от Umnico.

### Ручная проверка Direct — 21 ноября 2026 года

Пользователь выполнил диагностический сценарий для локального чата `1`
и предоставил результат:

```text
IMPORT OK: первый импорт +0, повторный +0; очередь без изменений
REPLAY OK: сохранённый результат возвращён дважды; новых отправок нет
>>> check_replay()
REPLAY OK: сохранённый результат возвращён дважды; новых отправок нет
```

Импорт через приложение завершился без ошибок дважды: новых записей и дубликатов
не добавлено, количество сообщений и состояние очереди не изменились. Повтор
запроса с сохранёнными `request_id` и текстом вернул `sent` без новых попыток
и записей вызова отправки к Umnico. Повторный запуск `check_replay()` также успешен.
Логи ручной отправки из панели в 11:05–11:06 того же дня подтверждают получение
исходящего webhook и сопоставление с попыткой по `customId`, чату и тексту.

Пользователь отдельно подтвердил, что второй `check_replay()` выполнен после
остановки и повторного запуска backend через `mise run start`. Повтор запроса
после перезапуска не создал новую отправку.

Для проверки добавления отсутствовавших сообщений Codex выполнил дополнительный
импорт того же реального Direct в пустую временную SQLite. Рабочая БД не открывалась
напрямую и не изменялась; новые сообщения не отправлялись.

| Дополнительная проверка | Результат |
| --- | --- |
| Импорт реальной истории в пустую базу | Добавлено 38 сообщений, все помечены как импортированные |
| Повторный импорт | Добавлено 0 сообщений |
| Задания, черновики и попытки отправки во временной базе | 0 |
| Повтор входящего webhook с ID реально импортированного сообщения | Дубликат; нового сообщения и задания нет |
| Сверка с перепиской рабочего backend через локальный API | Совпали все 38 messageId, направления, тексты и моменты времени; расхождение времени 0 секунд |

Добавление истории, дедупликация, совместимость `sentAt`/`messageId`, отсутствие
ответов на импорт, корреляция `customId` и повтор `request_id` после перезапуска
проверены. **Приёмка этих сценариев Direct завершена.** Ручной повтор без изменения
соответствующего механизма или интеграции не требуется.

Подробности и источник подтверждения сохранены в
[журнале прогресса](IMPLEMENTATION_PROGRESS.md) и [контракте Umnico](UMNICO_API.md).

### Оставшиеся ограничения и проверки

- Личный ответ после комментария требует подтверждения метода Umnico и реализации
  отправки. Пока создаётся черновик, а причина блокировки
  `comment_private_reply_unverified` отображается в панели.
- Материалы бизнеса нужно добавить в `knowledge_base/` и обновить базу через панель.
  Каталог не создаётся автоматически; при его отсутствии база знаний пустая.
- Контракт подписи webhook Umnico не подтверждён; используется отдельный секретный URL.
- Автоматический поиск всех старых обращений не реализован: импорт доступен
  для уже известного локального чата.

Расписание и проверка часов работы исключены из первой версии. Расчёт стоимости
и анализ изображений отложены.

Текущая автономная проверка 21 ноября 2026 года: **300 тестов прошли**, Ruff lint
и format-check успешны (42 Python-файла). Сначала прошли 110 целевых тестов
messaging/admin, затем полный набор. Из-за недоступности запуска mise проверки
выполнены напрямую установленными Python 3.13.18 и Ruff 0.17.3 из `.venv`,
без синхронизации зависимостей, кэшей в проекте и обращений тестов к реальным API.
Результат 274 относится к прежнему прогону. История проверок сохранена
в [журнале](IMPLEMENTATION_PROGRESS.md) и [документации Umnico](UMNICO_API.md).

## Следующие действия

1. Добавить материалы бизнеса и проверить поиск и ответы на реальных вопросах
   по ассортименту. Пока материалов нет, доступно выяснение потребности
   и сбор контактов без товарных сведений.
2. Подтвердить контракт личного ответа после комментария и реализовать отправку
   либо зафиксировать подтверждённое ограничение подключённого канала.
3. Уточнить контракт подписи webhook Umnico; дальнейшую доработку защиты
   определять по подтверждённой документации.

Это отдельные оставшиеся работы; завершённая приёмка Direct не объявляет их
выполненными. Проверки реальной отправки для новых сценариев требуют отдельно
выбранного тестового диалога.

## За пределами первой версии

- Расписание и проверка часов работы исключены из согласованного объёма.
- Расчёт стоимости и анализ изображений отложены; сроки и объём будущей реализации
  не определены.
- Автоматическое обнаружение всех старых обращений отсутствует и не входит
  в четыре согласованных шага как отдельная функция. Сейчас импортируется
  история известного локального чата; расширение требует отдельного решения.
