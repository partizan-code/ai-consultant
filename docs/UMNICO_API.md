# Интеграция Umnico

[Главная](../README.md) · [Настройка](SETUP.md) · [Архитектура](ARCHITECTURE.md) · [Риски](ROADMAP.md)

Приложение работает с подключённым Instagram через Umnico. Сводка относится
к текущему клиенту и проверенному тестовому аккаунту; другой аккаунт или канал
требует проверки прав и затронутых сценариев.

## Доступ и используемые методы

Базовый адрес — `https://api.umnico.com`. Доступ задаётся парой login/password
либо готовым JWT. Заголовок авторизации — `Authorization: JWT <token>`.
Login/password имеют приоритет; access/refresh обновляются клиентом и хранятся
только в памяти. Готовый JWT при истечении нужно заменить в конфигурации.

| Метод | Назначение |
| --- | --- |
| `POST /v2/auth/login` | Авторизация по login/password |
| `POST /v2/auth/tokens` | Обновление доступа |
| `GET /v2/integrations` | Интеграции аккаунта |
| `GET /v2/managers` | Сотрудники; выбор отправителя для аккаунта |
| `GET /v2/webhooks/` | Проверка регистраций webhook |
| `POST /v2/webhooks/` | Регистрация текущего URL приложения |
| `GET /v2/messaging/{lead_id}/threads` | Каналы обращения |
| `POST /v2/messaging/{lead_id}/history/{source_real_id}` | История канала |
| `POST /v2/messaging/{lead_id}/messages` | Текстовый ответ в существующий Direct |

При старте backend использует активный webhook с нужным URL либо создаёт его.
Остальные записи не изменяет и не удаляет. Отключённая совпадающая запись
и достижение лимита регистраций останавливают запуск с ошибкой. После смены
туннеля старые регистрации могут потребовать ручной очистки в Umnico.

## События и история

Обрабатываются входящие и исходящие сообщения Direct и комментариев.
Служебные события подтверждаются без создания ответа. Сохраняются доступные
логин клиента и контекст поста; токены из события не сохраняются.

История доступна для каналов уже известных обращений. Для чтения нужен внутренний
идентификатор канала Umnico; внешний идентификатор Instagram его не заменяет.
Неопределённый или неоднозначный канал блокирует операцию. История загружается
постранично; при ошибке уже сохранённые сообщения остаются в базе.
Импортированные сообщения не создают ответов, повторный импорт не создаёт дубликатов.
Клиент принимает пустую страницу с `cursor: null` как конец истории, если `source`
равен нулю или идентификатору запрошенного канала. Внутри приложения такой курсор
нормализуется в `0`. Отсутствующий курсор, `null` при наличии сообщений и чужой
источник не принимаются; проверки зацикливания и лимита страниц сохраняются.
После этой доработки пользователь подтвердил успешный импорт в проблемном чате
на подключённом аккаунте 21 ноября 2026 года.

## Отправка и подтверждение

Для отправки используются обращение, канал Direct, интеграция и сотрудник Umnico.
Перед подключением другого аккаунта нужно проверить сотрудника и настроить
`Settings.umnico_user_id`. Текущий выбор относится к проверенному тестовому аккаунту.

Приложение присваивает отправке собственный идентификатор, сохраняет её результат
и сопоставляет с исходящим событием. `customId` служит для сопоставления;
серверная защита Umnico от повторной отправки по нему не подтверждена.
Поэтому после тайм-аута или другого неопределённого результата отправку нельзя
повторять вслепую. Повтор сохранённого запроса через приложение возвращает
прежний результат без новой отправки.

`sent` означает принятие Umnico. Подтверждение исходящим событием не доказывает
прочтение ответа клиентом. Отправка текста, импорт, отсутствие дубликатов и повтор
запроса после перезапуска проверены на подключённом аккаунте. Результаты —
в [сводке приёмки](IMPLEMENTATION_PROGRESS.md).

## Неподтверждённые возможности и риски

- Метод личного ответа непосредственно после комментария не подтверждён;
  отправка личного ответа непосредственно после комментария заблокирована. При существующем единственном
  канале Direct доступен отдельный ручной ответ через него.
- Контракт подписи webhook неизвестен. Используется секретный URL приложения;
  его нельзя публиковать и сохранять в логах туннеля или прокси.
- Автоматический поиск всех старых обращений не реализован.
- Доступность и срок жизни ссылок на фото зависят от Umnico и его CDN.
- Права сотрудника, доступность каналов и ограничения аккаунта могут отличаться
  от тестового подключения. Не следует подбирать другой endpoint или повторять
  неизвестную отправку автоматически при расхождении с контрактом.

Используемые форматы запросов и проверки ответов находятся в
[umnico.py](../src/ai_consultant_bot/umnico.py) и
[events.py](../src/ai_consultant_bot/events.py). Изменение API сначала требует
проверки контракта; реальные отправки — отдельно согласованного тестового диалога.
