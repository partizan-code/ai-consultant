# Обновление SQLite для подсказок менеджеру

Миграция запускается отдельно и только при остановленном backend. Приложение
не изменяет прежнюю схему автоматически и сообщит о необходимости миграции.
Новая пустая база создаётся сразу с актуальной схемой.

1. Остановите backend и панель, убедитесь, что других процессов с этой SQLite нет.
   Сохраните версию приложения до обновления для возможного отката.
2. Сделайте резервную копию SQLite. Команда ниже использует SQLite Backup API,
   учитывающий журнал базы. Укажите настоящий путь, если он отличается от стандартного.
   Не перезаписывайте уже существующую резервную копию:

   ```console
   mise exec -- uv run --no-sync python -c "import sqlite3; from pathlib import Path; p=Path('data/consultant.sqlite3'); b=p.with_name('consultant.before-suggestions.sqlite3'); assert p.is_file() and not b.exists(); s=sqlite3.connect(p.resolve().as_uri()+'?mode=ro', uri=True); d=sqlite3.connect(b); s.backup(d); d.close(); s.close()"
   ```

3. После обновления исходников, при всё ещё остановленном backend:

   ```console
   mise exec -- uv run --no-sync python -m ai_consultant_bot.migrate_suggestions data/consultant.sqlite3
   ```

   Миграция удаляет прежнее хранилище ответов на одобрение и глобальную настройку
   автоответов, создаёт хранилище единственной текущей подсказки, добавляет версию
   задания и привязку попытки отправки к входящему. Если автоответы раньше были
   выключены, существующие переписки переходят на паузу. В противном случае их
   активность сохраняется. Сообщения, заявки, история и результаты попыток отправки
   сохраняются; неизвестные результаты продолжают блокировать отправку.
   Изменения атомарны; при нарушении ссылочной целостности выполняется откат.
   Повторный явный запуск безопасен.
4. Запустите backend и панель. Проверьте переписку, заявки, попытки отправки
   и переключатель активности. Новые переписки всегда создаются на паузе.

## Восстановление

Остановите backend и панель. Сохраните текущий файл и, если существуют, соседние
файлы `consultant.sqlite3-wal` и `consultant.sqlite3-shm` в отдельный каталог для
диагностики. Уберите эти файлы с прежнего пути, чтобы журнал новой базы не был
применён к восстановленной копии. Скопируйте резервный файл
`consultant.before-suggestions.sqlite3` обратно в `data/consultant.sqlite3`,
верните прежнюю версию приложения и только затем запускайте backend и панель.
Восстановление возвращает данные к моменту копирования; более поздняя переписка
в эту копию не входит. Резервный файл сохраните до завершения проверки.

Автоматические проверки миграции используют временные SQLite с сообщениями,
заявками и попытками отправки, проверяют оба прежних значения настройки,
повторный запуск, целостность и откат при ошибке. На рабочей базе миграция
в рамках разработки не запускалась.
