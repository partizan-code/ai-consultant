# Архитектура и API

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| FastAPI backend | Webhook, административный API и обработчик консультаций |
| Streamlit | Локальная панель одного администратора |
| SQLite | Переписка, заявки, настройки, задания и результаты отправок |
| Umnico | Приём событий Instagram, история и текстовая отправка Direct |
| OpenRouter | Генерация ответа и извлечение полей заявки |
| Локальная база знаний | Материалы бизнеса в Markdown, TXT и CSV |

Backend и панель работают отдельно. Панель обращается к локальному API,
backend — к Umnico и OpenRouter. Параметры задаются в `Settings`, секреты —
в проектном `.env` или переменных процесса. Запускается один процесс backend.

В панели история выбранного чата обновляется отдельным фрагментом каждые 3 секунды,
остальные данные — каждые 10 секунд. Успешная ручная отправка сразу обновляет историю
и перезапускает её таймер. До исходящего webhook ответ отображается из сохранённой
попытки `sent`; подтверждение заменяет это представление сообщением из истории.
Панель показывает последние `Settings.panel_page_size` сохранённых сообщений
(по умолчанию 50) без выбора страницы. Административный API сохраняет параметр `offset`.

## Обработка переписки

Входящее событие сохраняется, после чего обработчик подбирает историю, добавляет
полный загруженный набор материалов бизнеса, запрашивает модель и сохраняет заявку.
На паузе ответ сохраняется как одна текущая
подсказка на общую переписку в `suggestions`, с привязкой к исходному сообщению.
Активный бот отвечает автоматически в Direct без подсказки; после комментариев
автоматическая отправка заблокирована. Новые переписки создаются на паузе.

Direct и комментарии одного обращения Umnico объединяются в общую переписку
в пределах аккаунта и интеграции. Исходные каналы сохраняются для маршрутизации.
Одинаковый Instagram-логин не объединяет разные обращения. Общими являются
контекст консультации, карточка клиента, пауза и ограничения отправки.

Новое входящее сообщение делает прежнюю подсказку и генерацию неактуальными.
Очередь работает и на паузе. Переключение активности отменяет прежние задания,
версия `jobs.generation` защищает от запоздавшего результата для того же сообщения.
Пауза ставит неотвеченное сообщение в очередь; активация ничего не отправляет
и ждёт следующего входящего. Актуальность проверяется перед сохранением и отправкой.
Ручная отправка приостанавливает общение бота и отменяет прежнюю работу.
Импорт истории не создаёт заданий и не отвечает на старые сообщения.
Повторные события не создают дубликатов.

Контекст OpenRouter состоит из трёх сообщений: системная инструкция, JSON с полной
базой знаний и JSON с историей, карточкой клиента, сведениями о посте и `dialogue_state`. Материалы
остаются пользовательскими данными и не получают приоритет системных инструкций.
Документы имеют стабильный порядок по путям; поиск и нарезка не выполняются.
Неизменные инструкция и база образуют префикс для кеширования провайдером.

Для ручного ответа панель использует единственный связанный канал Direct.
При неоднозначном маршруте отправка блокируется. Менеджер переносит подсказку
в редактор, при необходимости меняет текст и отправляет обычным ручным запросом.
Общая переписка ставится на паузу до сетевого запроса, прежняя работа отменяется.
`outgoing_attempts.message_id` фиксирует, до какого входящего относится отправка: позднее
подтверждение не удаляет подсказку на более новое сообщение.

## Данные и надёжность

Заявка дополняется постепенно; пропуск поля и `null` не стирают уже известные данные.
Строка заменяет значение подтверждённой цитатой клиента. Для `furniture_type` и
`dimensions` операции `{"append":["цитата"]}` и `{"set":["цитата1","цитата2"]}`
добавляют или заменяют проверенные фрагменты, соединяя их через `; `.
Каждый новый фрагмент проверяется по входящим сообщениям; итог ограничен
`Settings.lead_field_max_chars`. Операция `{"clear":"цитата отзыва"}` явно очищает
поле во всех каналах общей переписки, чтобы старое значение не восстановилось
из другого канала. Новое значение и очистка одного поля одновременно недопустимы.
Обновления применяются только после проверки актуальности задания, одной транзакцией.

`dialogue_state.payment_options_mentioned` вычисляется по всей сохранённой исходящей
переписке и попыткам `sent`/`unknown`, независимо от ограничения истории модели.
Проверяются слова с основами `рассроч`, `кредит` и слово `частями`; это консервативный
признак упоминания, а не семантический классификатор любого предложения оплаты.
Неотправленные подсказки и попытки `failed`/`blocked` не учитываются. Признак помогает
не повторять предложение на «дорого», но не запрещает отвечать на прямой вопрос
об оплате. Соблюдение этого правила в тексте зависит от модели.

Лимит `reply` по умолчанию — 450 символов, он передаётся в системную инструкцию
из той же настройки, которую использует парсер. Превышение отклоняется до сохранения
заявки и отправки; автоматическое обрезание ответа не выполняется.

Консультант работает с диванами и связанными услугами. Факты бизнеса и минимальный
бюджет находятся в базе знаний; правила диалога, формат и ограничения — в системной
инструкции. Проверочные сценарии приведены в [CONSULTATION_CHECKS.md](CONSULTATION_CHECKS.md).

Модель и активность отдельных переписок сохраняются в SQLite. Материалы бизнеса загружаются
при старте и по команде из панели; при неудачном обновлении сохраняется предыдущий
успешный набор. Все загруженные документы передаются модели целиком; ответы по
ассортименту зависят от полноты и актуальности материалов и соблюдения моделью инструкции.

У сообщений сохраняется доступный контекст поста, включая ссылку на фото.
Фото отображается браузером и не передаётся модели для анализа.

Отправка учитывается до обращения к Umnico. Повтор того же запроса возвращает
сохранённый результат. При неопределённом исходе новые отправки в общей переписке
блокируются до подтверждения; слепого автоматического повтора нет.
`sent` означает принятие сообщения Umnico. Исходящее событие подтверждает
совпавшую отправку, но не прочтение сообщения клиентом.

## Доступ и API

Панель остаётся на localhost. Административный API требует
`Authorization: Bearer <ADMIN_TOKEN>`. При отсутствии токена операции отключены.
Webhook защищён отдельным секретным URL; контракт криптографической подписи
Umnico ещё не подтверждён. Access-log backend отключён; туннель и прокси тоже
не должны сохранять полный URL webhook.

| Метод | Назначение |
| --- | --- |
| `GET /health` | Доступность локального API |
| `POST /webhooks/umnico/{token}` | Приём событий Umnico |
| `GET /admin/chats` | Список общих переписок |
| `GET /admin/chats/{chat_id}` | Переписка, заявка, текущая `suggestion` (объект или `null`) и попытки отправки |
| `POST /admin/chats/{chat_id}/pause` | Пауза или возобновление общей переписки |
| `POST /admin/chats/{chat_id}/import-history` | Импорт истории связанных каналов |
| `POST /admin/chats/{chat_id}/send-text` | Ручная отправка по указанному каналу |
| `GET /admin/status` | Журнал обращений к API и последняя ошибка |
| `GET /admin/settings` | Текущая модель (`model`) |
| `PUT /admin/settings` | Изменение модели (`{"model": "provider/model"}`) |
| `POST /admin/knowledge/reload` | Атомарное обновление полных материалов бизнеса; ответ `{"documents": N}`, при ошибке 409 и сохранение предыдущей версии |

`chat_id` — локальный идентификатор приложения, не ID обращения Umnico.
Для прямых вызовов отправки нужен идентификатор подходящего канала: ID общей
переписки сам по себе не гарантирует маршрут Direct. Панель выбирает маршрут
из ответа API. Форматы запросов определены в
[web.py](../src/ai_consultant_bot/web.py), описание внешней интеграции —
в [UMNICO_API.md](UMNICO_API.md).

Обновление существующей SQLite выполняется отдельно при остановленном backend;
[резервное копирование, миграция и откат](MIGRATION_SUGGESTIONS.md). Startup
отказывается работать с прежней схемой до явной миграции.
