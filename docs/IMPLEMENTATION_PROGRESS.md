# Проверка готовности

[Главная](../README.md) · [Состояние и риски](ROADMAP.md) · [Запуск проверок](SETUP.md#проверки)

Актуально на 22 ноября 2026 года. Основные возможности первой версии реализованы.
Этот документ содержит текущую сводку готовности и границы проверки.

## Автономные проверки

Последний полный автономный прогон Python-кода — для релиза `7179303`,
развёрнутого в staging и production:

| Проверка | Результат |
| --- | --- |
| Python: backend, интеграции и панель | 476 тестов прошли через `mise run test` |
| JavaScript: прокрутка и клавиатура переписки | 27 тестов прошли |
| Ruff lint и format-check | Успешно |

Python-проверки выполнены на Python 3.13.18 через существующие mise + uv и
`.venv`, без синхронизации зависимостей и изменения lockfile. Ruff проверял
весь проект через `mise run lint` и `mise run format-check`. JavaScript-прогон:
`node --test tests/chat_scroll.test.cjs tests/chat_keyboard.test.cjs`.

Тесты выполнялись с синтетическими данными, временными базами и подменёнными
HTTP-транспортами либо перехватом соединения до сетевого ввода-вывода;
рабочая БД, `.env` и реальные API не использовались.

Добавлены проверки серверной конфигурации, запрета внешних API на staging,
прокси только для OpenRouter, отсутствия прямого обхода при его отказе,
приоритета подменённого транспорта и безопасных ошибок валидации URL прокси.

Реализованы подсказки менеджеру на паузе и автоответы активного бота в Direct.
Новые переписки создаются на паузе. Убраны одобрение ответов и глобальный режим;
подсказка запрашивается только кнопкой «Использовать подсказку» и сразу заменяет
текст редактора без подтверждения. Предпросмотр, хранение подсказок и фоновая генерация
на паузе удалены. API возвращает текст подсказки отдельным POST-запросом.
Тесты проверяют генерацию по нажатию, замену непустого редактора, сохранение текста
при ошибке, отсутствие генерации по таймеру, отмену устаревшей работы и ручную отправку.

Отдельная [миграция](MIGRATION_SUGGESTIONS.md) проверена на временной SQLite:
сохранение сообщений, заявок и попыток отправки, перенос активности,
идемпотентность и откат при ошибке ссылочной целостности. На рабочей базе
миграция не запускалась. Новое размещение панели проверено через AppTest;
полная визуальная приёмка обновлённого интерфейса в браузере ещё не проводилась.
Функциональная серверная проверка панели описана ниже.

Панель обновляет данные открытого раздела каждые 10 секунд без отдельной кнопки.
История переписки имеет отдельный интервал 3 секунды. После ручной отправки
она обновляется сразу, показывает последние сообщения и запускает
свой таймер заново. Принятый ответ виден до webhook без дублирования после подтверждения.
В ленте последние 50 сохранённых сообщений без переключателя страниц;
сообщения клиента слева, ответы справа. Подсказка выделена зелёным,
в редакторе обновлён плейсхолдер, уведомление об успешной отправке убрано.
Автопрокрутка отличает ручную прокрутку от сброса позиции при перерисовке
и повторно подключается при замене контейнера истории. Автономные проверки
покрывают временно пустую историю, новые сообщения и сохранение позиции при чтении.
Тесты покрывают появление новых чатов, восстановление после ошибок, сохранение
ввода и прокрутки, обновление доступности отправки и отсутствие повторной отправки
после потерянного ответа backend. Сохранённые настройки обновляются отдельно
от несохранённых изменений формы.

Тесты импорта покрывают завершение на пустой странице с `cursor: null`, в том
числе после нескольких страниц, отсутствие дубликатов и новых заданий на ответ.
Проверяются отклонение чужого источника и некорректных курсоров, безопасная
диагностика формата и отдельное сообщение об ошибке истории в панели.

## Проверка на подключённом аккаунте

- Подтверждены авторизация Umnico, получение Direct и комментариев через webhook,
  отправка текста в Direct и получение исходящего события.
- Проверены импорт отсутствовавшей истории, повторный импорт без дубликатов,
  соответствие сообщений и времени, отсутствие ответов на импорт.
- После исправления обработки пустой страницы с `cursor: null` пользователь
  подтвердил успешный импорт в чате, где ранее возникал `invalid_history_response`.
- Подтверждены сопоставление исходящего события с отправкой и повтор сохранённого
  запроса без новой отправки, включая повтор после перезапуска backend.
- Ранее пользователь проверил внешний вид панели и подтвердил, что он в порядке;
  это подтверждение относится к интерфейсу до размещения подсказки и редактора внутри окна.
- Пользователь проверил работу панели после перехода на автообновление каждые
  10 секунд и удаления кнопки «Обновить данные»; работа подтверждена.

Эти проверки закрывают приёмку перечисленных сценариев. Повтор без изменения
соответствующего поведения или интеграции не требуется.

## Приёмка VPS и переключение рабочего канала

По выводам команд и подтверждениям пользователя в серверном этапе 21–22 ноября:

- Развёрнуты отдельные staging и production; после обновления до одного SHA
  `3f4022c` сервисы активны, loopback `/health` отвечает `{"status":"ok"}`.
- Проверены вход в production-панель по HTTPS с Basic Auth и работа staging
  через SSH-туннель. Синтетическое сообщение staging сохранилось после перезапуска.
  Полная визуальная проверка всех состояний интерфейса этим не заявляется.
- Локальный backend остановлен, прежний активный webhook tuna отключён;
  зарегистрирован webhook `ai.exprofit.by`, подтверждено получение сообщений на VPS.
- После прямого HTTP 403 OpenRouter подключён через контейнер Xray с VLESS
  gRPC + REALITY. Через прокси получены HTTP 200 от публичного списка моделей
  и проверки ключа; пользователь подтвердил работу подсказок и автоответов в Direct.
- `nginx -t` и проверка systemd units успешны. Certbot timer активен, dry-run
  продления сертификата с `--run-deploy-hooks` завершился успешно.
- Созданы ручные копии SQLite staging и production, проверена целостность;
  отдельно для production-копии проверены восстановление во временный каталог
  и чтение сообщений. В рабочую базу копия не восстанавливалась.

Пути, версии и параметры контейнера записаны в [инструкции эксплуатации](DEPLOYMENT.md).
Автоматические и внешние бэкапы не настроены. Перезагрузка VPS, реальное падение
сервисов и практический откат релиза в этом этапе не проверялись.

## Границы готовности

22 ноября оба окружения обновлены с `3f4022c` до `7179303` без миграции базы.
После выполнения пользователем скрипта через sudo независимо проверены ссылки
релизов, четыре активных сервиса без перезапусков, backend и Streamlit health,
HTTPS Basic Auth (`401`) и закрытые служебные маршруты (`404`).
Новые бэкапы и journal повторно не читались из-за отсутствия беспарольного sudo.
Визуальная приёмка и реальные отправки для этого обновления не повторялись.

Качество консультаций по ассортименту ещё нужно проверить после загрузки материалов
бизнеса. Личная отправка после комментария и контракт подписи webhook не подтверждены.
Прочтение ответа клиентом и все возможные отказы реальной сети проверками не заявляются.
Изменение аккаунта или контракта Umnico требует проверки затронутых сценариев.
Текущие риски и дальнейшие действия собраны в [дорожной карте](ROADMAP.md).
