### Реализовано

- `config.py`: общие значения по умолчанию, проверка параметров, окружение и явно
  выбранный файл настроек без изменения окружения. Значения секретов исключены из repr.
- `storage.py`: семь таблиц SQLite; операции хранения чатов, сообщений, неполных
  заявок и настроек. Повторная инициализация не сбрасывает выбранную модель/режим.
  Для транзакций вызывающий код использует `with connection:`; соединения закрываются.
- `api_http.py`: тайм-ауты, запрет редиректов, безопасные ошибки без тела ответа,
  отсутствие автоматических повторов запросов.
- `umnico.py`: JWT, login, access/refresh в памяти, обновление перед истечением,
  повторный login при 401 обновления; GET интеграций и вебхуков.
- `openrouter.py`: текстовые chat completions, модель по умолчанию или переданный
  выбор, отклонение пустых/незавершённых ответов.
- `main.py`: загрузка конфигурации, `--env-file` и явная инициализация `--init-db`.
- Добавлены автономные тесты конфигурации, временной SQLite и клиентов HTTPX
  с MockTransport. Smoke-тесты запускают приложение без унаследованных секретов.
- В `pyproject.toml` добавлены HTTPX и python-dotenv; README обновлён.

Таблицы черновиков, заданий и обращений к API — только схема: обработка,
заполнение журнала и панель относятся к следующим шагам. Защита от повторной
записи сообщения пока действует в пределах локального чата; окончательный ключ
дедупликации входящих событий нужно согласовать с контрактом Umnico на шаге 2.

## Шаг 2 — 20 ноября 2026 года

Пользователь явно согласовал реализацию шага 2. Режим DEVELOPMENT. Реализован код

### Реализовано

- `events.py`: разбор наблюдаемых `message.incoming` и предварительной структуры
  `message.outgoing` (по аналогии с входящим; требует сверки), различение
  Direct и комментария, необязательное превью/ссылка на пост. `lead.changed` и прочие
  уведомления не создают повторных сообщений; исходный JSON и `source.token` не хранятся.
- `storage.py`: добавлены таблицы контекста сообщений и попыток отправки без изменения
  существующих таблиц. Дедупликация входящего потока по аккаунту, интеграции и messageId
  выполняется в `BEGIN IMMEDIATE`, независимо от webhookId и изменения leadId.
  Уникальность messageId в этой области — рабочее допущение по наблюдаемой структуре;
  официальная гарантия Umnico пока не получена.
- Новое входящее текстовое сообщение создаёт задание; входящее событие делает
  черновики устаревшими. Захват заданий учитывает паузу, активное задание и неизвестную
  отправку в чате. Исполнитель заданий/генерация ответа относятся к шагу 3.
- `messaging.py`: последовательный импорт страниц известного локального чата,
  проверка контекста источника, лимит страниц и обнаружение цикла cursor.
  Импорт помечается `imported`, не создаёт заданий и не запускает ответы при повторном
  получении уже импортированного сообщения через webhook. Успешно сохранённые страницы
  остаются при ошибке последующей страницы. Поиск всех старых обращений не реализован.
- Ручная отправка через постоянный `request_id`: попытка фиксируется до HTTP-запроса,
  ставит бота на паузу и делает черновики устаревшими. Повтор ID не повторяет HTTP;
  изменённое содержимое с тем же ID отклоняется. Тайм-аут/прерывание, 5xx и непонятный
  успешный ответ оставляют `unknown`; новые отправки этого чата также блокируются.
  Вызовы истории/отправки записываются в `api_calls` без тел и секретов.
- `umnico.py`: предварительные методы истории и отправки из разделов 5–6 документации;
  отдельные флаги `UMNICO_HISTORY_VERIFIED` и `UMNICO_SEND_VERIFIED` по умолчанию false
  запрещают запросы ещё до авторизации. Внутренние ID в URL ограничены положительными
  числами; для отправки требуется явно выбранный числовой `UMNICO_USER_ID`.
- Личный ответ на комментарий остаётся заблокированным с сохранённой причиной
  `comment_private_reply_unverified`. Комментарий не отправляется в публичный канал
  под видом личного ответа. Сверки исходящего webhook с попыткой по customId пока нет.
- `web.py`: FastAPI lifespan с инициализацией SQLite/закрытием HTTP-клиента, публичный
  `/health`, приём `/webhooks/umnico/{token}`, административные import-history/send-text
  с отдельным Bearer-токеном, безопасные ошибки и ограничение размера тела.
  Пустые токены отключают соответствующие операции. URL webhook содержит отдельный
  случайный секрет: это временная защита доступа, не подтверждённая подпись Umnico.
- `main.py`: явный `--serve`, по умолчанию localhost:8000; access-log отключён, чтобы
  не раскрывать секретный URL. В `config.py` добавлены параметры сервера, лимиты и флаги;
  в `pyproject.toml` — требуемые FastAPI/Uvicorn. README содержит запуск и контракты API.
- Добавлены тесты событий, повторов и конкурентной доставки, импорта, паузы/очереди,
  устаревания черновиков, отправки/отмены/неизвестного результата, конфликтов request_id,
  блокировок непроверенных операций и ASGI-маршрутов с аутентификацией.

## Доработки запуска и регистрации webhook — 20 ноября 2026 года

По явному запросу пользователя изменён сценарий запуска; этот раздел уточняет
описанный выше первоначальный запуск шага 2.

- `config.py` автоматически читает `.env` в корне исходного проекта. Из файла и
  окружения загружаются только шесть полей секретов: учётные данные Umnico,
  ключ OpenRouter, ADMIN_TOKEN и WEBHOOK_TOKEN. Секреты окружения имеют приоритет;
  прочие ключи игнорируются. Настройки задаются через `Settings` в Python.
  Пароль сохраняется без обрезки пробелов; интерполяция и поиск файлов отключены.
- Удалены argparse и аргументы запуска приложения, а также неиспользуемое поле
  `umnico_webhook_url`. `mise run start` запускает приложение без параметров.
  `main(settings, tunnel_url)` позволяет явно передать параметры программно.
- Обычный запуск требует WEBHOOK_TOKEN и учётные данные Umnico, запрашивает текущий
  HTTPS-адрес туннеля без пути, добавляет секретный путь и запускает API. Адрес не
  сохраняется в `.env`. Регистрация выполняется после готовности локального сервера.
- `UmnicoClient.ensure_webhook`: GET списка, проверка совпадающего URL, один POST
  при отсутствии записи. Сравнение учитывает регистр хоста, порт 443 и конечный `/`.
  Имеющиеся записи не изменяются и не удаляются. Отключённая совпадающая запись,
  лимит и некорректные ответы дают безопасную ошибку. Нет автоматического повторного
  POST после тайм-аута; следующий запуск вновь проверит список. В лог попадают только
  результат и ID записи, без полного URL/токенов.
- При ошибке регистрации или запуска сервер останавливается; ожидание готовности
  и завершения ограничено настройками тайм-аутов. Отдельно обработан SystemExit,
  который Uvicorn использует при неудачном старте.
- `scripts/generate_admin_token.py` и `scripts/generate_webhook_token.py` запускаются
  вручную без аргументов и печатают строку для переноса в `.env`. Они не читают и не
  меняют файл, приложение не генерирует токены автоматически. Обновлены `.env.example`,
  README и задача start в mise. Зависимости и lockfile в этой доработке не менялись.
