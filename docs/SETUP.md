# Установка и настройка

[Главная](../README.md) · [Панель](ADMIN_PANEL.md) · [Состояние и риски](ROADMAP.md)

Все команды выполняются из корня репозитория. Backend и панель запускаются
отдельными процессами; для webhook нужен публичный HTTPS-туннель tuna.

## Подготовка окружения

Python 3.13 управляется через mise, зависимости и `.venv` — через uv.
Установите mise и uv, затем выполните:

```console
mise trust
```

Если Python 3.13 ещё не установлен через mise:

```console
mise install python@3.13
```

Подготовьте окружение:

```console
mise run setup
```

Команда выполняет `uv sync`, устанавливает зависимости из конфигурации проекта
и подготавливает `.venv`. `uv.lock` хранится в репозитории; `.venv` между машинами
не переносится. Автоматическое скачивание Python отключено, поэтому интерпретатор
нужно установить заранее. Команды запуска и проверок используют `--no-sync`.

## Секреты и настройки

Создайте `.env` по [.env.example](../.env.example). Существующий файл не перезаписывайте:
добавляйте только недостающие значения. Не включайте секреты в Git.

| Значение | Назначение |
| --- | --- |
| `UMNICO_LOGIN`, `UMNICO_PASSWORD` | Пара для входа в Umnico |
| `UMNICO_API_KEY` | Альтернатива login/password: JWT с префиксом `JWT` либо без него |
| `OPENROUTER_API_KEY` | Генерация консультаций через OpenRouter |
| `ADMIN_TOKEN` | Доступ панели к административному API |
| `WEBHOOK_TOKEN` | Секретный путь приёма webhook |

Login/password имеют приоритет над API key и задаются вместе. `ADMIN_TOKEN`
и `WEBHOOK_TOKEN` должны быть разными. Для их генерации доступны команды:

```console
mise exec -- uv run --no-sync python scripts/generate_admin_token.py
mise exec -- uv run --no-sync python scripts/generate_webhook_token.py
```

Перенесите выведенные значения в `.env`. Скрипты не меняют файл автоматически.
`.env` читается из корня исходного проекта; секреты из переменных процесса имеют
приоритет. Другие настройки задаются в `Settings` в
[src/ai_consultant_bot/config.py](../src/ai_consultant_bot/config.py).

По умолчанию backend слушает `127.0.0.1:8000`, панель — `127.0.0.1:8501`,
база находится в `data/consultant.sqlite3`, материалы — в `knowledge_base/`.
Начальная модель — `openai/gpt-6.1-sol`, автоответы в новой базе выключены.
Выбранные через панель модель и режим сохраняются в базе и не сбрасываются
при перезапуске. Относительные пути данных зависят от рабочего каталога запуска.

Для другого аккаунта Umnico нужно проверить сотрудника-отправителя и изменить
`Settings.umnico_user_id`; текущее значение относится к проверенному тестовому аккаунту.

## Запуск

1. Откройте в tuna HTTPS-туннель на локальный порт `8000`.
2. Выполните `mise run start` и введите текущий HTTPS-адрес туннеля без пути.
3. Во втором терминале выполните `mise run panel`.
4. Откройте [127.0.0.1:8501](http://127.0.0.1:8501).

Backend при старте подготавливает SQLite и проверяет регистрацию webhook Umnico.
Для запуска нужны учётные данные Umnico и `WEBHOOK_TOKEN`; для панели нужен
`ADMIN_TOKEN`. Без ключа OpenRouter приём сообщений работает, но консультации
не обрабатываются и задания остаются в очереди.

Запускайте один процесс backend, без нескольких Uvicorn workers. Панель остаётся
на localhost; через туннель публикуется только backend. При смене адреса туннеля
старые webhook не удаляются автоматически. Полный URL webhook содержит секрет:
не публикуйте его и не сохраняйте в логах туннеля или прокси.

После обновления зависимостей выполните `mise run setup`. После изменения кода
перезапустите затронутые процессы. Перед переносом или изменением базы сделайте
резервную копию; при штатном запуске приложение подготавливает необходимые таблицы.

## Материалы бизнеса

Поместите материалы в `knowledge_base/` и нажмите «Обновить базу знаний»
в настройках панели. Поддерживаются Markdown, TXT и CSV в UTF-8, включая подпапки.
В CSV первая строка содержит названия столбцов. Без каталога база знаний пустая;
бот может уточнять потребность и собирать контакты без сведений об ассортименте.
При неудачном обновлении сохраняется предыдущий успешно загруженный набор материалов.

## Проверки

```console
mise run check
```

Команда запускает Ruff lint, проверку форматирования и Python-тесты. Доступны
также `mise run lint`, `mise run format-check` и `mise run test`.
Тесты используют синтетические настройки, временные базы и подменённую сеть.

Отдельные тесты JavaScript требуют установленного Node.js и запускаются командой:

```console
node --test tests/chat_scroll.test.cjs
```

В `mise run check` они не входят. Для работы приложения Node.js не требуется.
Последние результаты проверок — в [сводке готовности](IMPLEMENTATION_PROGRESS.md).
