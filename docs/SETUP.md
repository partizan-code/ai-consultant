# Установка и настройка

[Главная](../README.md) · [Панель](ADMIN_PANEL.md) · [Состояние и риски](ROADMAP.md)

Все команды выполняются из корня репозитория. Backend и панель запускаются
отдельными процессами; для webhook нужен публичный HTTPS-адрес: туннель tuna
локально либо постоянный домен на [VPS](DEPLOYMENT.md).

## Подготовка окружения

Python 3.13 управляется через mise, зависимости и `.venv` — через uv.
Установите mise и uv, затем выполните:

```console
mise trust
```

Если Python 3.13 ещё не установлен через mise:

```console
mise install python@3.13
```

Подготовьте окружение:

```console
mise run setup
```

Команда выполняет `uv sync`, устанавливает зависимости из конфигурации проекта
и подготавливает `.venv`. `uv.lock` хранится в репозитории; `.venv` между машинами
не переносится. Автоматическое скачивание Python отключено, поэтому интерпретатор
нужно установить заранее. Команды запуска и проверок используют `--no-sync`.

## Секреты и настройки

Создайте `.env` по [.env.example](../.env.example). Существующий файл не перезаписывайте:
добавляйте только недостающие значения. Не включайте секреты в Git.

| Значение | Назначение |
| --- | --- |
| `UMNICO_LOGIN`, `UMNICO_PASSWORD` | Пара для входа в Umnico |
| `UMNICO_API_KEY` | Альтернатива login/password: JWT с префиксом `JWT` либо без него |
| `OPENROUTER_API_KEY` | Генерация консультаций через OpenRouter |
| `ADMIN_TOKEN` | Доступ панели к административному API |
| `WEBHOOK_TOKEN` | Секретный путь приёма webhook |

Login/password имеют приоритет над API key и задаются вместе. `ADMIN_TOKEN`
и `WEBHOOK_TOKEN` должны быть разными. Для их генерации доступны команды:

```console
mise exec -- uv run --no-sync python scripts/generate_admin_token.py
mise exec -- uv run --no-sync python scripts/generate_webhook_token.py
```

Перенесите выведенные значения в `.env`. Скрипты не меняют файл автоматически.
`.env` читается из корня исходного проекта; переменные процесса имеют приоритет.
`AI_CONSULTANT_ENV_FILE` в окружении процесса выбирает другой файл; отсутствующий
явно указанный файл вызывает ошибку, без перехода к локальному `.env`.

Через файл или окружение задаются также `APP_ENV` (`local`, `staging`, `production`),
`PUBLIC_BASE_URL`, `REGISTER_WEBHOOK` (`true`/`false`), `SERVER_HOST`, `SERVER_PORT`,
`PANEL_PORT`, `DATABASE_PATH`, `KNOWLEDGE_BASE_PATH`, `LOG_LEVEL`, `UMNICO_USER_ID`.
Другие параметры по-прежнему задаются в `Settings` в
[config.py](../src/ai_consultant_bot/config.py). Значения не интерполируются.

Для серверного режима нужны абсолютные пути данных и материалов и
`SERVER_HOST=127.0.0.1`; в production обязателен HTTPS origin `PUBLIC_BASE_URL`
без пути. Если `APP_ENV` задан процессом как staging/production, требуется
явный `AI_CONSULTANT_ENV_FILE`. Backend и панель используют один файл окружения.
Staging блокирует оба внешних API и обработчик консультаций независимо от ключей
и флага регистрации. Порты, каталоги и учётные записи окружений разделены в
[инструкции размещения](DEPLOYMENT.md).

По умолчанию backend слушает `127.0.0.1:8000`, панель — `127.0.0.1:8501`,
база находится в `data/consultant.sqlite3`, материалы — в `knowledge_base/`.
Начальная модель — `openai/gpt-6.1-sol`, новые переписки создаются на паузе.
Поведение задаётся переключателем активности каждой общей переписки.
Для существующей базы сначала выполните [миграцию при остановленном backend](MIGRATION_SUGGESTIONS.md).
Выбранная модель и активность отдельных переписок сохраняются в базе и не сбрасываются
при перезапуске. Относительные пути данных зависят от рабочего каталога запуска.

Для другого аккаунта Umnico нужно проверить сотрудника-отправителя и изменить
`UMNICO_USER_ID`; текущее значение относится к проверенному тестовому аккаунту.

## Запуск

1. Откройте в tuna HTTPS-туннель на локальный порт `8000`.
2. Выполните `mise run start` и введите текущий HTTPS-адрес туннеля без пути.
3. Во втором терминале выполните `mise run panel`.
4. Откройте [127.0.0.1:8501](http://127.0.0.1:8501).

Backend при старте подготавливает SQLite и по умолчанию проверяет регистрацию
webhook Umnico. Если задан `PUBLIC_BASE_URL`, интерактивного запроса адреса нет.
`REGISTER_WEBHOOK=false` отключает регистрацию и запрос адреса, но в local/production
не запрещает входящие события и отправку. На staging регистрация всегда выключена.
Для запуска нужны учётные данные Umnico и `WEBHOOK_TOKEN`; для панели нужен
`ADMIN_TOKEN`. Без ключа OpenRouter приём сообщений работает, но консультации
не обрабатываются и задания остаются в очереди.

Запускайте один процесс backend, без нескольких Uvicorn workers. Панель остаётся
на localhost; через туннель публикуется только backend. При смене адреса туннеля
старые webhook не удаляются автоматически. Полный URL webhook содержит секрет:
не публикуйте его и не сохраняйте в логах туннеля или прокси.

После обновления зависимостей выполните `mise run setup`. После изменения кода
перезапустите затронутые процессы. Перед переносом или изменением базы сделайте
резервную копию. Новая база создаётся с актуальной схемой; существующая база
прежней версии требует явной миграции по инструкции выше.

Интервал обновления истории — `Settings.panel_history_refresh_interval` (3 секунды),
остальных данных — `Settings.panel_refresh_interval` (10 секунд). В ленте отображаются
последние `Settings.panel_page_size` сохранённых сообщений (50 по умолчанию).
Эти параметры задаются в Python, а не в `.env`.

## Материалы бизнеса

Поместите материалы в `knowledge_base/` и нажмите «Обновить базу знаний»
в настройках панели. Поддерживаются Markdown, TXT и CSV в UTF-8, включая подпапки.
В CSV первая строка содержит названия столбцов. Без каталога база знаний пустая;
бот может уточнять потребность и собирать контакты без сведений об ассортименте.
При неудачном обновлении сохраняется предыдущий успешно загруженный набор материалов.

Все непустые файлы передаются модели целиком при каждой консультации, без нарезки
и поиска по словам. CSV передаётся в исходном виде вместе с заголовками. Файлы
читаются при запуске backend и по кнопке обновления; изменения на диске применяются
после обновления. Панель сообщает число загруженных документов.

Лимиты в `Settings`: `knowledge_max_chars` — 50 000 символов суммарно,
`knowledge_max_documents` — 100 документов, `knowledge_file_max_bytes` — 1 МиБ на файл.
Превышение отклоняет обновление целиком, без обрезки материалов. Это ограничения
размера локальной базы, а не проверка токенного окна модели: при выборе модели нужно
учитывать также инструкцию, историю, данные поста и место для ответа.

Инструкция и полная база расположены перед меняющейся историей диалога, образуя
стабильный префикс для кеширования. По [документации OpenRouter](https://openrouter.ai/docs/guides/best-practices/prompt-caching)
кеширование для OpenAI-моделей автоматическое; у других провайдеров условия могут
отличаться. Текст всё равно отправляется в каждом запросе. Попадание в кеш и экономия
не гарантируются. Их можно проверить в OpenRouter Activity или по
`usage.prompt_tokens_details.cached_tokens` в ответе API; приложение эту метрику
пока не сохраняет.

## Проверки

```console
mise run check
```

Команда запускает Ruff lint, проверку форматирования и Python-тесты. Доступны
также `mise run lint`, `mise run format-check` и `mise run test`.
Тесты используют синтетические настройки, временные базы и подменённую сеть.

Отдельные тесты JavaScript требуют установленного Node.js и запускаются командой:

```console
node --test tests/chat_scroll.test.cjs
```

В `mise run check` они не входят. Для работы приложения Node.js не требуется.
Последние результаты проверок — в [сводке готовности](IMPLEMENTATION_PROGRESS.md).
